# ซิงค์ v2 ขึ้น Google Sheets

## สรุปสั้น ๆ ว่าทำไมต้องแยกจาก v1

สร้าง **สเปรดชีตใหม่** ไม่ใช้ของ v1 เดิม เพราะ

1. v1 ยังใช้งานจริงอยู่จนกว่าจะย้าย ถ้าไปแก้สคริปต์เดิมแล้วพลาด คือหยุดงานทั้งโรงงาน
2. โครงรายการเคลื่อนไหวของ v2 ไม่เหมือน v1 — v1 มี `direction` แค่ IN/OUT ส่วน v2 มีเจ็ดชนิด
   มีล็อต มีเหตุผล และมีทั้งยอดที่นับได้กับส่วนต่างสำหรับการปรับยอด
   ถ้าเอามาปนชีตเดียวกันจะอ่านย้อนหลังไม่รู้เรื่องทั้งสองฝั่ง

ของเดิมใน v1 อยู่ครบเป็นบันทึกย้อนหลังต่อไป **ไม่ต้องย้ายและไม่ต้องลบ**

## ติดตั้งครั้งแรก

1. สร้างสเปรดชีตใหม่ ตั้งชื่ออะไรก็ได้ที่แยกออกจากของเดิม เช่น `Bin Card v2`
2. ส่วนขยาย → Apps Script → ลบโค้ดตัวอย่างทิ้ง → วาง `apps-script.gs` ทั้งไฟล์
3. แก้บรรทัด

   ```js
   var TOKEN = 'CHANGE-ME-1234';
   ```

   เป็นรหัสของตัวเอง — เดายากหน่อย และห้ามใช้ซ้ำกับของ v1
4. Deploy → New deployment → เลือกชนิด **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. ก๊อป URL ที่ลงท้ายด้วย `/exec` มาใส่ในหน้า "ซิงค์" ของโปรแกรม พร้อม TOKEN ที่ตั้งไว้
6. กด **ทดสอบการเชื่อมต่อ** ถ้าขึ้นชื่อสเปรดชีตแปลว่าใช้ได้

## แก้สคริปต์รอบถัดไป

> **Manage deployments → กดรูปดินสอ → Version: New version → Deploy**

URL เดิม**ไม่เปลี่ยน** ไม่ต้องไล่แก้ทุกเครื่อง

⚠️ อย่ากด **New deployment** ใหม่ เพราะจะได้ URL ใหม่ แล้วต้องเดินไปแก้ทุกเครื่องเอง
และเครื่องที่ยังไม่ได้แก้จะซิงค์ขึ้นชีตเก่าเงียบ ๆ โดยไม่มีอะไรเตือน

⚠️ กด Ctrl+S ในหน้า Apps Script อย่างเดียว **ไม่พอ** — โค้ดที่เซฟไว้ยังไม่ถูกใช้จนกว่าจะดีพลอย

## ชีตที่จะถูกสร้างให้อัตโนมัติ

| ชีต | กุญแจ | เก็บอะไร |
|---|---|---|
| `Entries` | `id` | รายการเคลื่อนไหวทั้งเจ็ดชนิด |
| `Materials` | `material_code` | ทะเบียนวัตถุดิบ **ทั้งหมด** รวมที่ปิดใช้งานแล้ว |
| `BOM` | `id` (`pn\|code`) | สูตร ลบด้วยการติดธง `deleted` ไม่ใช่ลบแถว |

## กฎที่ห้ามแก้

**ไม่มีคำสั่งไหนในสคริปต์นี้ที่เขียนทับทั้งตาราง** — ทุกอย่าง upsert ทีละแถว

v1 เคยส่งทะเบียนขึ้นแบบล้างทั้งชีตแล้วเขียนกลับเฉพาะรหัสที่ active
ผลคือรหัสที่ปิดใช้งานหายจากเซิร์ฟเวอร์ถาวร และเป็นรากของ INVARIANTS E3
ซึ่งลามไปจนพนักงานเจอทางตันทุกครั้งที่มีของนอกรายการเข้ามา

**ห้ามลบคอลัมน์ `id` / `material_code` และ `updated_at`**
ตัวแรกคือกุญแจที่ใช้ upsert ตัวหลังคือสิ่งที่ทำให้ดึงเฉพาะของที่เปลี่ยนได้

**เพิ่มคอลัมน์ใหม่ให้ต่อท้ายเสมอ อย่าแทรกกลาง**
สคริปต์เติมหัวที่ขาดให้เอง แต่ข้อมูลเดิมใต้หัวเก่าจะไม่เลื่อนตามถ้าแทรกกลาง

## เทส

```bash
node tests/v2-sync.test.mjs
node tests/v2-sync-server.test.mjs
```

ตัวหลังโหลด `apps-script.gs` มารันจริงบนชีตปลอมในหน่วยความจำ
เพราะโค้ดฝั่งนั้นอยู่บนเครื่องของ Google แก้แล้วต้องกดดีพลอยถึงจะเห็นผล
ถ้ารอเจอบั๊กตอนใช้จริง แปลว่าเจอตอนข้อมูลของพนักงานหายไปแล้ว
